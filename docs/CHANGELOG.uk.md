# Журнал Змін

[English version](CHANGELOG.md)

## Невипущені Зміни

### Виправлення

- Delete прибирає дані без постійної заборони для обох джерел: upstream
  повертається за запитом, local — після повторної публікації та погодження.
  Схема 11 прибирає старі Deleted/tombstone, зберігає Blocked та аудит, скидає
  завершення каталогу й фіксує походження для захисту від підміни local модулем
  upstream. Видалення та публікація не скасовують Blocked; адміністратор може
  явно розблокувати ресурс навіть після видалення його даних.
- Додано сумісність із розбіжністю namespace metadata official Forge за явного
  правильного slug і збігу назви модуля та версії. Нормалізується лише API-назва;
  контрольні суми архіву й інші поля зберігаються. Покрито apt 0.0.1, 0.0.2 та
  10.0.0, старий кеш, колекції й окремі релізи без ручних виключень і змін
  валідації локальної публікації.
- Паралельні захищені запити очікують до п'яти секунд на поточне оновлення
  конфігурації доступів, якщо придатного snapshot немає, замість негайного 503.
  Придатний snapshot використовується без очікування; скасування або таймаут
  очікування не дозволяють обійти перевірку доступу.
- Невідомі upstream-модулі індексуються за першим точним запитом колекції V3
  незалежно від фільтра версії, offset або порожнього доступного результату.
- Схема 11 атомарно зберігає версії та завершення каталогу; міжреплікова lease
  перевіряється в транзакції, а lifecycle повторно перевіряється перед commit.
- Збережено локальне походження та явні блокування. Delete скидає завершення
  каталогу для повторного отримання upstream на вимогу. Невдалий імпорт можна
  повторити; 404 дає порожню колекцію.

- Повна metadata upstream-релізів зберігається й перевіряється в колекціях V3
  та окремих релізах, включно із залежностями, вимогами й додатковими полями.
- Старі SQL-записи доповнюються навіть із заповненим file URI; ремонт
  серіалізований між репліками й не перезаписує конкурентні зміни артефакту.
- Недоступна чи невалідна обов'язкова metadata повертає контрольовану помилку
  замість неповної успішної відповіді або неперевіреного upstream fallback.
- URI архівів і пагінації V3 відносні до кореня зі збереженням фільтрів та null
  для відсутніх сторінок, відповідно до очікувань installer OpenVox 8.

### Тести

- Перший запит, дві репліки, помилки й повторні спроби, lifecycle-гонки та атомарний
  rollback каталогу покриті PostgreSQL/SQLite-тестами. Стандартний fixture OpenVox
  тепер починає без upstream-модулів і кешованих upstream-архівів.

- Додано регресії metadata, кешу, пагінації, upstream-помилок і конкурентності.
- Додано opt-in Docker-тест стандартного installer OpenVox 8 і smoke
  авторизованого Forge. Справжній Common і повний check sshd із resource coverage
  залежать від середовища й не вважаються перевіреними лише через наявність тестів.
- Дослідження періодичного 503 залишається окремим; причина не стверджується.
